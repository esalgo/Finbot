# FinBot

Conversational financial assistant for a fintech operating in Colombia and the United States. It answers in the language of each message, fetches live market data, runs investment calculations, searches a knowledge base on Colombian financial regulation, and analyzes financial documents attached as images.

Every answer shows **where it comes from** (knowledge base, live data, calculation, image analysis, cache, or the model's general knowledge), and while the agent is working the UI shows **what it is actually doing**.

## What it does

| Capability | How |
|---|---|
| Knowledge base (RAG) | Deposit insurance (Fogafín), Bre-B and instant payments, credit cards, electronic deposits, account seizures, usury rate. Always cites the source entity. |
| USD exchange rate | `get_usd_rate` — open.er-api.com, no credentials |
| Stocks | `get_stock_quote` — Finnhub (NYSE ADRs for Colombian companies: `EC`, `CIB`, `AVAL`) |
| Crypto | `get_crypto_price` — Coinbase, in any currency (e.g. bitcoin in pesos) in a single call |
| Compound interest | `calculate_interest` — own logic; the model never does the math |
| Images | Bank statements, invoices, receipts and screenshots of financial apps. Any other image is declined without being described. |
| Memory | Conversation per `thread_id`, in the LangGraph checkpointer |
| Semantic cache | Curated FAQ of 5 questions, generated by the same agent; conversations are never stored |
| Daily limit | Global, in Postgres; text = 1 unit, image = 3 |

Voice is not included: the audio phase was skipped. The `audio` field stays in the contract and is always `null`.

## Architecture

```
Angular 22 frontend ──► POST /api/chat/stream (SSE)
                         │   proxy strips the /api prefix
                         ▼
FastAPI backend
  1. validates the message and the image (magic bytes, MAX_IMAGE_MB cap)
  2. semantic cache (skipped when there is an image) ── hit ──► answers and writes the turn into the thread
  3. consumes daily quota (text 1, image 3) ── exhausted ──► 429
  4. LangGraph graph
       parse_input → image? → vision | agent (+ tools) → finalize
  5. events: status (thinking / tool / vision / writing) … final (the /chat contract)
                         │
Postgres + pgvector ◄────┘  rag_documents · semantic_cache · usage_daily · checkpoints*
```

- **Chat and vision model:** DeepSeek (`deepseek-chat`) through an OpenAI-compatible API. Swappable from `.env`; vision has its own optional provider (`VISION_BASE_URL`, `VISION_API_KEY`).
- **Embeddings:** always OpenAI (`text-embedding-3-small`, 1536 dimensions), with their own key. They never go through the chat provider.
- **Images are never stored:** they travel in the LangGraph run context, not in the state — verified against the checkpointer tables. The browser does not store them either.
- **Small images are upscaled in the browser** to 1,600 px on the longest side before sending: at low resolution the model confuses digits.

## Getting started (development)

Requirements: Python 3.12, Node 24 with pnpm 11.25.0, Docker.

```bash
# 1. Database (applies schema.sql on first start)
docker compose -f compose.dev.yaml up -d

# 2. Python environment (a single venv at the root; must be 3.12)
python3.12 -m venv .venv
.venv/bin/pip install -r requirements/backend.txt -r requirements/ingest.txt -c requirements.lock.txt

# 3. Environment variables
cp backend/.env.example backend/.env    # LLM_API_KEY, OPENAI_API_KEY, FINNHUB_API_KEY
cp scripts/.env.example scripts/.env    # OPENAI_API_KEY

# 4. RAG corpus (put the .txt files in data/sources/ first — see below)
cd scripts && ../.venv/bin/python ingest.py --dry-run   # fetch and count chunks only
../.venv/bin/python ingest.py && cd ..

# 5. Backend (http://localhost:8000)
cd backend && ../.venv/bin/fastapi dev src/main.py

# 6. Frontend (http://localhost:4200), in another terminal
cd frontend && pnpm install && pnpm start
```

The backend refuses to start if a required variable is missing or if `rag_documents` does not exist yet (run the ingestion first). On startup it generates the semantic cache answers in the background.

## `data/sources/`: manually captured sources

The RAG corpus has two input paths with identical metadata:

- **Scraping** (`ingest.py`): 4 pages from Fogafín and Nu that can be fetched. Each site has its own CSS selector; ingestion fails if a page does not return 200 or if the selector finds no content.
- **Local files** (`data/sources/*.txt`): pages that cannot be fetched automatically (bot blocking, JavaScript-rendered content or Cloudflare protection), copied by hand from the browser.

**The `sources/` folder is in `.gitignore`**: those files are verbatim copies of third-party pages (Banco de la República, Superintendencia Financiera, Nequi) and are not versioned.

What this means when cloning the repo:

- `data/sources/` arrives **empty**. `ingest.py` does not fail when it finds no files: it ingests only the scraped sources, and the RAG ends up without Banco de la República's Bre-B content, the usury rate, electronic deposits and account seizures.
- To get the full corpus, capture the files again before ingesting. Each `.txt` has three header lines, a blank line and the body, with paragraphs separated by blank lines.

```
source_url: https://www.banrep.gov.co/es/bre-b/preguntas-frecuentes
entidad: Banco de la República
fecha_captura: 2026-09-12

¿Qué es Bre-B?

Bre-B identifica, en los canales de las entidades financieras, …
```

Sources captured by hand: Bre-B FAQ and the usury rate glossary entry (Banco de la República), electronic accounts and deposits (Superintendencia Financiera), and account seizures and releases (Nequi help center). Use the browser's reader mode before copying, and update `fecha_captura`: it is the only thing that reveals stale content.

## API

Both endpoints take the same body:

```json
{ "message": "¿A cuánto está el dólar?", "thread_id": "uuid", "image": "data:image/png;base64,… (optional)" }
```

- `POST /chat` → `{ "response", "tools_used": [], "cached": false, "audio": null }`
- `POST /chat/stream` → SSE events: `status` (`thinking`, `tool` with its name, `vision`, `writing`), then `final` with the same contract, or `error`.
- `422` invalid message or image · `429` daily limit reached (message in Spanish and English) · `502` agent failure.

## Frontend

Angular 22 standalone app (zoneless and OnPush by default), generated with the Angular CLI and pnpm, **without SSR**: the production build is static files served behind a proxy.

### Commands

Run from `frontend/`:

| Command | What it does |
|---|---|
| `pnpm install` | Installs dependencies from `pnpm-lock.yaml` (pnpm version pinned in `package.json`: `packageManager`) |
| `pnpm start` | Dev server on http://localhost:4200 with live reload; `/api/*` is proxied to the backend on port 8000 |
| `pnpm ng test --watch=false` | Runs the Vitest suite once |
| `pnpm ng build` | Production build into `dist/frontend/browser` |
| `pnpm ng generate component <name>` | Scaffolds a component (see `pnpm ng generate --help`) |

The dev server needs the backend running; without it every message ends in a connection error bubble.

### Structure

```
src/
├── index.html, main.ts, styles.css   entry point and global styles (all styling lives in styles.css)
└── app/
    ├── app.ts / app.html              the whole chat screen: header, suggestions, messages, progress card, composer
    ├── app.config.ts                  app providers (no HttpClient: the chat uses fetch)
    └── chat/

        ├── chat.service.ts            POST /api/chat/stream with fetch; parses SSE events
        ├── chat.store.ts              message history signal, thread id, sending state, localStorage persistence
        ├── tool-labels.ts             tool names → labels/icons, progress wording, origin banner rules
        ├── markdown.ts                minimal markdown renderer that escapes HTML first
        └── image-prep.ts              upscales small images with canvas before sending
```

### How a message flows

1. `App.submit()` hands the text (and the prepared image, if any) to `ChatStore.send()`.
2. The store appends the user message **by replacing the array** (`messages.update(list => [...list, msg])`); mutating it in place would not repaint under OnPush.
3. `ChatService.stream()` posts to `/api/chat/stream` and reads the response body as a stream. Each `status` event updates `ChatStore.status` and the list of tools consulted, which the progress card renders; `final` resolves with the same contract as `/chat`.
4. The assistant message is appended with its `toolsUsed` and `cached` flags. The origin banner and the tool badges are computed from those two fields only — never from the answer text.
5. 422, 429 and 502 responses become error bubbles with the backend's message.

### What is stored in the browser

- `localStorage` key **`finbot.chat.v1`** holds the `thread_id` and the message history. The thread id is saved together with the messages: without it, a reload shows the old conversation while the backend starts a new thread that remembers nothing.
- **Never stored:** attached images, audio and error bubbles. A message that had an image keeps only a `hadImage` flag.
- If the stored format changes, bump the key version instead of trying to parse old data.
- "Nueva conversación" clears the history and creates a new thread id.

### Adding a tool to the UI

When the backend gains a tool, add it to `TOOL_LABELS` in `chat/tool-labels.ts` (label, icon and progress sentence) and, if it belongs to a new kind of source, to `originsOf()`. An unknown tool still renders a generic badge and is never labeled as model knowledge.

### Images

Accepted: JPEG, PNG, GIF and WebP up to 5 MB (the backend validates again). Images whose longest side is under 1,600 px are redrawn on a canvas at that size and sent as PNG (JPEG if the PNG would exceed 5 MB); larger images are sent untouched. The preview shows the exact image that will be sent.
